# 安全、API 防刷与费用保护

## 使用时机与边界

开放 API、AI 生成、上传/下载、搜索接口或收费功能前；异常流量、账单上涨、越权或第三方嵌入接口时使用。先只读调查；扫描、封禁、改权限、生产配置和可能影响真实用户的测试按授权执行。

保护资产包括用户数据、账号、订单/额度、服务端密钥、文件、算力、邮件配额和带宽。文字规则不能替代服务端控制，WAF/CDN 也不能替代业务权限。

## 最小威胁分析

对每条入口记录调用者、可访问对象、可消耗资源、信任边界、最坏成本、已有控制与缺口。攻击者可能是匿名用户、登录用户、被盗账号或嵌入接口的其他产品，不能只看来源站点。

## 必查控制

1. 认证与授权分开：登录成功不代表能访问任意对象。每次关键读取/写入在服务端校验对象归属、租户和角色。
2. 输入验证：类型、长度、数量、文件大小、内容类型和允许值；避免注入、路径穿越和用户输入被当作可信执行指令。
3. 密钥只在安全服务端配置中使用，最小权限、按环境隔离；不能出现在前端 bundle、截图、错误栈、日志和公共仓库。
4. 会话、Cookie、CSRF、跨域策略按认证方式与框架官方做法核实。CORS、Referer、隐藏 URL、浏览器按钮禁用不是鉴权机制。
5. 公开上传需鉴权/配额、类型与实际内容校验、随机对象键、私有访问策略，必要时恶意内容检测；处理失败和孤立文件清理。
6. 后端抓取用户 URL 时检查 SSRF 风险：协议、私网/本地/元数据地址、重定向、DNS 变化、响应大小和超时，不能只检查初始字符串。
7. AI/付费调用的权限、余额、并发和预算服务端执行；避免多请求同时检查余额后重复扣费或超发。
8. 日志保留足够定位的请求/任务标识、状态和时延，去掉凭据与不必要个人信息；错误提示不暴露内部细节。

有数据库输入时核查参数化查询和 SQL 注入路径；有用户内容渲染时核查 XSS、输出编码及 HTML 清理；CSRF、SSRF、文件上传和管理权限按实际入口分别检查，不用一个“输入已验证”代替全部专项。检查应有代码位置或受控测试依据，不能只凭搜索不到关键字认定安全。

检查环境配置时，只核对变量名称、是否存在、用途、环境归属及必要结构。不要把完整 .env、认证头、Cookie、支付凭据或云配置原值打印到工具输出再尝试遮罩。需要读取秘密值的测试应在不回显的安全路径执行；工具不能保证时停在结构核对并列出人工步骤。报告只写泄漏位置和处理建议，不复制泄漏内容。

## 防刷分层

| 层级 | 可选措施 | 注意 |
| --- | --- | --- |
| 请求入口 | IP/账号/API Key/租户分层限速 | IP 共享和分布式调用，不能只按单 IP |
| 业务资源 | 用户额度、单任务上限、日/月预算 | 限流不等于限制总费用 |
| 并发 | 同时任务数、队列长度和超时 | 限制重试、失败任务不能无限堆积 |
| 幂等 | 请求/业务事件标识与唯一约束 | 重复点击或回调不能重复扣费/发权益 |
| 分发 | 合适缓存、签名下载、源站访问限制 | 防盗链不能单独保护私密内容 |
| 异常检测 | 错误率、来源分布、用量、带宽、费用告警 | 先确定基线和负责人 |
| 处置 | 暂停高成本入口、收紧配额、封禁证实滥用者 | 说明影响、误伤与恢复办法 |

限速应返回清楚的受限信息，适用时提供重试提示。计数位置和持久性必须匹配部署：多实例不能假设单进程内存计数全局有效。避免把新计数存储当作无条件依赖，先评估现有能力。

CDN 用量封顶或自动熔断可能让全部图片停止服务。预算告警也未必是硬封顶。核实供应商实际能力，明确额度、延迟、误差和达到后的行为，经用户确认后配置。不能擅自创建“每小时巡检”自动任务或永久黑名单。

## 已发生异常时

先保留必要证据、区分真人高峰与滥用，查看接口、来源、任务和成本路径。对最贵入口提出有限范围的缓解，预估用户影响；紧急处置也不能借机获得无限生产权限。

不要只凭 UA 或 Referer 拉黑，也不要把 User-Agent 宣称的爬虫当真。对已证实滥用记录规则、时间、到期/复核和恢复途径。

## 验证与报告

在获准环境中验证无登录访问、跨用户/租户访问、非法输入、超限、重复请求、并发扣减、失败重试和恢复。不能对第三方系统做未授权测试。

输出风险、证据位置、可利用前提、业务影响、严重性、最小修复、验证和剩余风险。已确认越权、凭据泄漏、可无限消耗高成本资源通常阻塞发布；不承诺“绝对安全”。可参考 [OWASP REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。
