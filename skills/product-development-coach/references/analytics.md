# 统计、用户行为与工具成本

## 什么时候用

准备上线需了解访客来源；要分析注册、使用、留存与付费；比较国内/海外工具；两个平台数字不同；免费额度不足或数据遗漏时使用。没有明确分析问题时先不安装统计 SDK。

## 先定义问题与口径

基础流量回答“多少人、从哪里来、看了什么”；产品分析回答“是否完成核心操作、在哪里流失、是否回来、是否付费”。工具可能同时具备多类能力，不能用简单品牌标签代替当前功能核实。

定义时间范围、时区、用户/会话/事件、访客识别、重复事件、内部流量、爬虫、拒绝追踪、采样和过滤规则。UV 通常是某规则下估计的去重访客，不是绝对真实人数。

同一访问被两个平台各记一次，不代表发生两次；不能直接相加 PV、UV 和事件数。一个平台漏报、另一个自动采集更多，也可能产生差异。跨平台汇总先统一口径、身份映射和事件去重，再说明误差。

例如 100 人各浏览 3 页，在同一口径下是 300 PV；两个平台各报告 300，不能得到 600 次真实浏览。这是说明口径的假设例子，不是对任意平台的准确保证。

## 选型前收集

- 中国大陆、海外或混合市场；实际访问网络、管理后台可达性。
- 基础流量还是漏斗/留存/分群，是否真需要录屏和热力图。
- 事件量、保留期限、站点数、项目数、数据导出和删除需求。
- 预算、云托管或自托管、数据最终存储和处理区域。
- 用户告知、同意或其他适用依据，不能用本文件代替法律判断。

候选可包括百度统计、GA4、Umami、PostHog、Matomo、神策、GrowingIO，但不固定“地区 → 唯一供应商”。按当前官方能力、真实网络测试、总成本和维护能力决定。

MVP 通常先选一个能回答核心问题的来源。只有明确分工、缺口和合并规则后才建议第二个平台；不能默认购买重复服务。自托管也有服务器、升级、安全、备份和人力成本。

## 网络与隐私判断

脚本加载、事件上报、后台访问分别检查，不能只 ping 一个域名就宣布稳定。使用自有域名代理可能改善某些请求路径，但不改变数据最终存储位置，也不自动满足跨境或隐私要求。

“不使用 Cookie”不等于所有地区、所有配置都无需告知或同意。需要按地区、数据、用途和当前可信法规来源核实；查不到时明确未确认，不给笼统法律保证。

不向统计发送密码、Token、付款资料、完整邮箱/手机号、用户正文、带敏感查询参数的 URL。假名标识也可能涉及个人数据。录屏须考虑遮罩、表单、内部页面和额外授权，不默认开启。

## 事件设计

为每个事件记录：名称、业务含义、触发时机、客户端/服务端来源、属性白名单、去重键、负责人和验证方法。

| 事件示例 | 正确触发 | 易错点 |
| --- | --- | --- |
| page_view | 约定的页面进入或路由变化 | 首屏自动采集又手动上报 |
| signup_completed | 服务端确认注册成功 | 点击注册按钮就算成功 |
| generation_started | 任务实际被接纳 | 同一重试重复算新任务 |
| generation_succeeded | 结果已可用 | 请求发出就算成功 |
| checkout_started | 支付会话实际创建 | 按钮曝光当购买意向 |
| payment_succeeded | 可信服务端付款确认 | 前端跳转成功页算收入 |

名字是可选约定，沿用项目已存在的含义优先。事件量不等于 PV；自动采集、重试、业务事件会增加额度消耗。财务以可信订单与支付对账为依据，统计后台不替代账本。

## 费用核实表

逐供应商核对当前免费条件、计费单位、站点限制、数据保留、超额后停止/收费行为、录屏等独立额度、导出、最低消费、续费和预算封顶。附官方链接与核实日期，不把旧聊天价格写死。

两个独立平台是否都付费取决于所选服务和合同；不能擅自说有联名套餐或买一个自动包含另一个。每月与全年成本分开估算，免费额度和超额假设明确。

## 验证与交付

在获准测试环境中执行一条真实流程，核对首屏/路由只计一次、成功失败分开、属性无敏感信息、拒绝追踪行为符合约定、前后台可对账。不同地区网络未实测就标记未验证。

输出 [ANALYTICS.md](../templates/ANALYTICS.md)、工具选择依据、费用表、事件字典、核验结果和未确定合规事项。验收是能回答既定问题且数据采集有证据，不是“装了脚本就算完成”。
