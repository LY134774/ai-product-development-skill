# Skill 行为测试场景

`cases.json` 收集产品开发、交接、SEO/GEO、支付、上线审计以及**不应触发**的场景。每条记录有用户输入、预期参考指南、希望观察的行为、禁止行为。

## 现在能验证什么

```bash
python -B scripts/validate_evals.py
```

该命令只检查测试用例**数据结构、ID、路由文件存在性与正反样例覆盖**，不能证明 Codex 真正读取或遵守规则。

## 如何进行真实 Codex 评测

1. 在全新的测试项目和独立聊天中安装指定版本，不用正式生产仓库。
2. 将每条 `input` 单独输入 Codex，先测试**显式调用**，随后测试未提 Skill 名的自动触发。
3. 保存输出及可审计操作记录，按 `should` 和 `must_not` 逐项评判；必要时检查文件差异。
4. 对生成的文件、测试命令和权限边界进行人工复核，不仅看回答措辞。
5. 在 `evals/results/` 创建日期化的结果文件，注明模型、宿主、版本、运行环境及未验证项。
6. 如果发现行为回归，先修复并重新评测，再增加发行说明。结果文件不可包含密钥、客户数据或私人聊天全文。

建议记录：场景 ID、Skill 版本、宿主与模型、是否自动触发、预期/实际路由、禁止行为是否发生、通过/失败/未验证、证据位置。不要把人工规则核对叫作真实 Agent 评测。
