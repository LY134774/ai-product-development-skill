# 技术架构与成本：按产品选择，不照抄技术清单

## 何时加载

MVP 确定后选型；用户问数据库、登录、邮件、模型、图片存储、CDN、Meilisearch 等是否需要；或现有架构出现已证实瓶颈时加载。已有项目优先沿用已确认方案。

## 最小输入

用户地区、公开/内部产品、页面渲染需求、数据关系、文件体积、搜索体验、同步需求、AI 任务耗时、预期规模、预算上限、部署环境、维护能力。规模未知时写出假设和重新评估条件，不用想象中的百万用户设计第一版。

## 比较方法

每项技术说明：解决的问题、MVP 是否必需、推荐理由、更简单替代、接入与维护成本、数据区域、迁移和退出办法、证据链接与核实日期。只比较真正可行的少数方案。

| 能力 | 先判断 | 更简单的起点 | 何时升级 |
| --- | --- | --- | --- |
| 前后端框架 | 是否需要公开内容、SEO、复杂交互或服务端逻辑 | 沿用项目技术；简单静态页不必有后端 | 证实有新运行或渲染需求 |
| 数据库 | 是否要持久化、跨设备、关联查询和事务 | 单机原型可用适当本地方案 | 多用户、持久性、备份和查询需求增加 |
| 搜索 | 搜什么、语种、相关性、拼写容错、筛选、延迟 | 数据库索引与自身搜索能力 | 实测质量或速度不足，能负担独立索引同步 |
| 登录 | 是否确需身份、权限和用户数据隔离 | 无账号原型或已存在认证体系 | 有明确归属、安全和访问控制需要 |
| 邮件 | 验证、密码恢复还是营销邮件 | 没有邮件场景就不接入 | 真实业务需要，核实域名、送达和费用 |
| AI 模型 | 文本/图像、质量、时延、数据使用、单次成本 | 用真实样例比较当前可用模型 | 质量或成本指标支持切换 |
| 文件存储 | 部署磁盘是否持久、文件是否私密、多实例是否共享 | 本地原型可用受控持久目录 | 正式用户文件、多实例或无持久磁盘部署 |
| CDN | 地区、体积、回源、可缓存内容、访问控制 | 先优化资源与源站，按实测决定 | 异地延迟、流量和容量确有需要 |
| 后台任务 | 是否长耗时、需重试、是否超出请求时间 | 小任务可同步，保留超时边界 | 长任务需持久状态、重试和并发控制 |
| MCP 服务 | 是否有已确定的外部 Agent 调用场景 | 普通网页/API 即可 | 有明确集成需求且授权接入 |

Next.js、TypeScript、PostgreSQL、Better Auth、Resend、Meilisearch、COS、S3、R2 等只能是候选，不是强制组合。不要因模型“熟悉某框架”而承诺不出错。网站代码放在同一应用，不等于数据库、搜索和对象存储也属于同一进程或一次部署。

## 存储与 CDN 要说清楚

数据库可以保存文件的业务归属、对象键、状态和元信息；对象存储负责文件本体。不要把会过期的签名下载地址当作永久文件标识。私人文件不能因“方便加载”变成公共桶。

本地保存是否适合生产取决于持久化、备份、多实例、恢复能力；不能一概说本地一定丢，也不能在临时文件系统承诺永久保存。上传还要考虑体积、类型、数量、鉴权、恶意内容和清理策略。

对象存储和 CDN 的计费项可能分开：存储、请求、下载、回源、数据取回、转换和日志等。不要把所有流量相加造成重复估算；按供应商当前账单路径核对。CDN 不会自动解决源站鉴权或全部跨境数据问题。

独立搜索增加索引构建、更新/删除同步、权限过滤、备份、监控和运行内存。数据库是事实来源，搜索索引可重建；必须定义同步失败和重建策略。不能只用条目数量断言一定需要 Meilisearch。

## 成本表与技术交付

列一次性接入、固定月费、按量费用、免费额度与超额行为、存储/流量/备份、人工维护、退出成本。自托管软件许可免费不等于服务器、运维和升级免费。

以实际使用单位估算：请求量 × 单次成本、事件量 × 保留期限、文件量 × 平均体积、流量 × 缓存命中假设；高低两种情景并注明是假设，不编造确定报价。各平台分别核算，套餐是否覆盖必须查证。

输出组件职责图、请求/数据流、服务清单、权限边界、部署方式、费用假设和替代方案。核心选择经确认才写入 DECISIONS；安装、注册、开通计费和更改生产环境仍需相应授权。

验收：每个组件都有明确必要性；数据保存与备份可解释；关键成本无遗漏；用户理解推荐、简单替代与以后升级条件。
