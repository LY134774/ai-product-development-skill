# 支付、订阅、额度与权益审计

## 何时使用

用户明确需要商业化、支付、会员、按量计费、退款或排查付款失败时。没有真实收费需求的 MVP 不自动添加支付；只做审计不修改结算、税务或支付平台配置。

先确认商户所在地区与资质、用户地区、币种、一次性/订阅/额度制、税务责任、退款政策、权益周期、支付方式和预算。Stripe 等只是候选，不承诺任意国家/账号都可用或自动支持某种支付方式。

## 商业规则先写清

- 套餐的内容、额度、有效期、是否结转、过期与退款后的处理。
- 按次扣减在任务接纳、完成还是其他节点发生；失败、取消、重试和重复任务如何补偿。
- 免费赠送是否按用户、月份或注册发放；定义服务端周期与时区，不能无限重复领取。
- 订阅升级、降级、取消、欠费、到期与续费的权益时间点。
- 一次性购买固定期限与自动续费是两种产品，界面必须真实说明，不能只按页面语言悄悄改变付款约定。
- 定价和税费需用户确认；不能抄朋友的固定赠送额度或价格。

## 可信支付流程

1. 前端提交套餐/商品标识及必要选择，不信任客户端传入的价格、币种、用户身份、折扣和权益。
2. 服务端根据可信套餐配置与当前用户权限确定金额和币种，创建内部订单并绑定用户。
3. 用获准的服务端凭据创建支付会话；考虑重复点击的幂等，记录内部订单与平台对象关联。
4. 用户完成托管结账；成功跳转页只展示状态，不能单凭 URL 参数、浏览器事件或前端回调发放权益。
5. 服务端验证平台通知的真实性与业务含义，核对环境、商户、订单、用户、币种、金额及付款状态。
6. 通过持久唯一约束、事务和状态转换保证同一业务付款只生效一次；不能只用内存 Set 或前端按钮控制。
7. 处理重复、重试、乱序与延迟事件，支持对账与补偿；到账、账本和权益变更可追溯。

## 回调与状态

按提供商当前官方方式验签。签名校验如要求原始请求体，应在 JSON 转换前保留正确字节；不为通过测试而绕过验签。Webhook 签名密钥与 API 调用密钥用途不同，不混用。

不要按 API Key 字符前缀自行判断能否接收付款通知；最小权限凭据是否足够通过实际权限核实。正式与测试环境的 key、对象、回调、商品和数据库记录必须隔离。

先可靠接纳事件，再按平台要求及时响应；异步处理应持久记录，失败可恢复。订阅、异步付款和退款的事件语义不同，不能把所有“完成”事件都理解成最终到账。支持的事件与字段按当前 API 版本查证。

订单至少区分待支付、已支付、失败/取消、退款等实际业务状态；具体模型按产品制定。额度账本应记录来源事件、增加/扣减、余额约束和关联业务，不只覆盖一个余额字段而失去审计。

## 退款、订阅与自助门户

退款要核对原订单、可退金额、幂等、权益回收和审计记录。部分退款、争议、取消订阅与立即失效是不同状态；不能自动作出不曾约定的处理。

客户自助门户的会话由服务端绑定当前用户，不能相信客户端传入的任意 customer ID。处理升级降级和计费周期时，先说明计费与生效规则，避免意外收费。

托管收银台可减少自行处理付款信息的范围，但不免除商户的权限、安全、隐私、税务和业务责任。

## 版本、地区与费用核实

查看当前账号/地区支持的一次性支付、自动续费、钱包、支付宝或微信等能力；不能把旧聊天里的支付方式限制当作永恒规则。Managed Payments、名义卖家、税码和附加费等都必须核实具体账号和合同，不能为了“能付款”擅自关闭税务功能或扩大密钥权限。

正式切换前确认账号审核、结算、商品、币种、税费、回调地址、环境凭据、最小权限和监控。测试通过不能证明正式账号可用；真实扣款、退款和账号变更需单独授权与限定金额。

## 必要测试矩阵

| 场景 | 要检查 |
| --- | --- |
| 正常购买 | 可信价格、订单与用户对应、权益准确 |
| 客户端篡改 | 低价、错误币种、他人订单或套餐不能生效 |
| 无效通知 | 错签名、错误环境、金额不符不发权益 |
| 重复/并发通知 | 只记一笔业务付款和一份权益 |
| 乱序/重试 | 状态不倒退、不丢账、可恢复 |
| 失败/取消/延迟 | 不提前开通，界面能反馈和重试 |
| 退款/争议 | 按确认政策调整账本和权益 |
| 订阅续费/欠费/取消 | 周期和生效时间正确 |
| 额度并发与失败 | 不超扣、不超发，失败按政策补偿 |

先用提供商沙盒与官方测试资料，不在生产使用测试卡或模拟真实扣款。修改计费核心逻辑后运行相关回归，报告实际执行范围。

输出确认业务规则、风险路径、文件/日志证据、测试结果、未验证正式条件和回滚办法。签名绕过、客户端定价、重复发权益等未解决时阻塞发布。参考 [Stripe Webhooks](https://docs.stripe.com/webhooks)，具体 SDK 与 API 参数使用时复核。
